## Why

The current 5G candidate still uses synthetic delay, throughput, and PLR. Since
the local ns-3.45 workspace has no NR/5G-LENA module, the next best step is a
clearly labeled 5G proxy flow whose traffic metrics are generated by ns-3
rather than hard-coded curves.

This improves integration realism without pretending to reproduce real NR.

## What Changes

- Add a 5G-like proxy traffic path for candidate index `0`.
- Feed 5G proxy delay, throughput, and PLR from FlowMonitor.
- Keep 5G SINR/RSRP from the existing hypothetical-gNB propagation proxy.
- Keep the ns3-ai message schema unchanged.
- Keep the Python runner unchanged unless CLI-only plumbing is required.
- Update runtime logs and OpenSpec records to label this candidate as
  `5G proxy`, not real NR.

## Capabilities
