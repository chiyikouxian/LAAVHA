## Message Contract

C++ to Python:

```cpp
struct LaavhaEnv
{
    float metrics[150];   // 3 networks * 10 timesteps * 5 metrics
    float velocity;
    float altitude;
    int currentNet;
};
```

Python to C++:

```cpp
struct LaavhaAct
{
    int targetNetId;      // 0: 5G, 1: LTE, 2: WiFi
    float score5g;
    float scoreLte;
    float scoreWifi;
};
```

Network IDs:

- `0`: 5G
- `1`: LTE
- `2`: WiFi

Metric order per network per timestep:

```text
SINR, RSRP, Delay, Throughput, PLR
```

Flattening order:

```text
network -> timestep -> metric
```

This means Python should reshape `metrics` to:

```python
x_status = np.array(metrics, dtype=np.float32).reshape(1, 3, 10, 5)
```

## Python Model

Use the `LAAVHA_Net` structure from `/home/suwen/reproduce/LAAVHA改进算法训练程序.py`, not the incompatible `LAAVHAPredictor` from the old inference script.

Expected model call:

```python
S_pred, weights = model(x_status_tensor, mobility_tensor)
```

Shapes:

- `x_status_tensor`: `(1, 3, 10, 5)`
- `mobility_tensor`: `(1, 2)`
- `S_pred`: `(1, 3, 5)`
- `weights`: `(1, 5)`

Model loading:

```text
/home/suwen/reproduce/LAAVHA算法模型.pth
```

The model may not match exactly. If loading fails:

- Print the exception clearly.
- Continue with randomly initialized weights.
- Mark the run as a smoke test fallback.

## Decision Logic

Use a simple deterministic scorer so the integration is reviewable:

1. Convert `S_pred[0]` to a `(3, 5)` array.
2. Treat these columns as:
   - benefit: SINR, RSRP, Throughput
   - cost: Delay, PLR
3. Min-max normalize each column across the 3 networks.
4. For cost columns, invert normalized values.
5. Multiply by `weights[0]` and sum per network.
6. Select the highest score.

Add defensive handling:

- Use epsilon when max equals min.
- Clamp non-finite values.
- Ensure target is always in `[0, 1, 2]`.

## C++ Smoke Simulation

The C++ simulation should:

- Use a fixed RNG seed.
- Run for a short duration, e.g. 3s or 5s.
- Use decision interval `0.1s`.
- Populate all 150 metrics each cycle.
- Send the environment struct to Python.
- Receive the action struct.
- Print current time, current network, target network, and scores.
- Increment `handover_count` when target differs from current.
- Print a final summary.

All logs should clearly say:

```text
LAAVHA ns3-ai integration smoke test
```

Do not describe it as a complete Chapter 3 reproduction.

## Review Notes

The architecture reviewer should pay special attention to:

- Whether C++ and Python struct field names/types match the pybind bindings.
- Whether the reshape order matches the declared metric contract.
- Whether fallback model loading is explicit and not silently hiding failures.
- Whether the C++ target can be built independently by `./ns3 build ns3ai_laavha_handover`.
