# LAAVHA Scheduled Mobility Skeleton

## Why

The current LAAVHA example has completed the first integration milestone: ns-3 can exchange messages with Python, the LAAVHA model loads, Python returns a target network, and C++ prints handover statistics.

However, the C++ side is still a plain `for` loop with synthetic values. It does not yet behave like an ns-3 simulation:

- no `Simulator::Schedule`
- no `Node`
- no `MobilityModel`
- velocity and altitude are generated by formulas rather than read from ns-3 state

Before adding real network devices and PHY/FlowMonitor metrics, the simulation should be moved onto an ns-3 scheduled execution skeleton while preserving the working ns3-ai message contract.

## What

Refactor the existing LAAVHA smoke-test C++ example to use ns-3 simulation primitives:

- create UAV node(s)
- install a mobility model
- schedule the decision loop every `0.1s`
- read velocity and altitude from the mobility model
- keep the existing Python interface and model/scoring code stable
- keep synthetic metrics for now, but derive their trend from simulation time and/or UAV position

This stage is still not a full Chapter 3 reproduction. It is the bridge from "communication smoke test" to "ns-3 simulation skeleton".

## Non-goals

- Do not add real LTE/WiFi/5G devices in this change.
- Do not add FlowMonitor statistics in this change.
- Do not implement full TOPSIS or comparison algorithms in this change.
- Do not change the Python message schema unless absolutely required.
- Do not modify the original files in `/home/suwen/reproduce`.

## Deliverables

- `laavha-handover.cc` refactored from loop-based execution to `Simulator::Schedule` execution.
- A UAV node with a mobility model.
- Velocity and altitude passed to Python from the mobility model.
- The existing Python runner continues to work.
- A run log showing scheduled decisions and final summary.

## Success Criteria

- `./ns3 build ns3ai_laavha_handover` succeeds.
- `python laavha_inference.py` runs the scheduled ns-3 simulation.
- The C++ output shows scheduled decision times from `Simulator::Now()`.
- Python receives changing velocity/altitude values sourced from ns-3 mobility state.
- The simulation completes and prints summary statistics.
- The message contract remains:

```text
metrics[150], velocity, altitude, current_net -> target_net_id, score_5g, score_lte, score_wifi
```
