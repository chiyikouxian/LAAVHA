# 新场景为何支持两次必要切换

主任务是 50 s 的三阶段遥感任务：无人机由东向西飞行，先经 NR 区巡航，再在 Wi-Fi 站点附近低速成像，最后由 LTE 支持返程。算法根据网络观测和当前业务选择接口；程序没有指定迁移顺序、迁移时刻或次数上限。

## 实际运行的场景

| 项目 | 主配置 |
|---|---|
| NR / LTE / Wi-Fi 站点 | (1500,1000,30) / (700,1000,30) / (1000,1000,10) m |
| 无人机起点 | (1600,1000,100) m，水平偏移 ±30 m、高度偏移 ±10 m，每个任务采样一次 |
| 路线 | 向西，名义终点 x=450 m；速度 30→5→25 m/s，两处各用 1 s 连续过渡 |
| 成像业务 | 地理区间 950≤x≤1000 m 内 8 Mbps；其他位置 2 Mbps 预览 |
| 遥测业务 | 全程 64 kbps，截止时间 50 ms；视频截止时间 200 ms |
| 建筑 | x=1100–1150、y=900–1100、z=0–75 m；射线穿实体时附加 18 dB 损耗 |
| LTE 回传 | 6 Mbps，形成与成像需求有关的资源差异 |
| 决策与迁移 | 每 0.1 s 决策；应用端点迁移中断 100 ms |
| 无线实现 | 真实 5G-LENA NR、LTE/EPC、802.11n；工程 log-distance 传播 |

三个共址移动无线节点代表一个逻辑无人机。探测接口保持连接，但每个有效载荷包只通过被选接口发送到共同服务器。迁移会真正改变发送端点，并记录中断造成的包损失。中断时长是显式应用模型参数。

## 为什么调整建筑高度

85 m 屋顶时，第三个开发种子出现 NR 已退化、Wi-Fi 尚未接续的短暂区间。独立参考和八种控制器都选择 NR→LTE→Wi-Fi→LTE，共三次。这是覆盖接续问题，结果保存在 `outputs/physical_pilot_height85/`。

主场景将屋顶降到 75 m，以提供更充足的覆盖重叠。以名义高度 100 m 和 y=1000 m 为例，从无人机到 NR 站点的射线在建筑东侧 x=1150 m 处的高度为

`z = 100 - 70 × (1150-x)/(1500-x)`。

该高度降到屋顶时，85 m 屋顶对应无人机 x≈1054.5 m；75 m 屋顶对应 x≈955.6 m。前者接近 Wi-Fi 初次接续区间，后者允许 NR 支持更长的重叠段。这个几何计算解释调整机理；最终可用性仍由实际 PHY 和包测量确定。位置、高度扰动会改变这些位置。

## “理想两次”的证据

先运行固定 NR 的物理校准，再对它记录的三个候选状态使用独立动态规划。参考效用是 `4×遥测服务满足度+视频服务满足度`，计入中断和每次 0.02 的切换成本。它允许任意网络顺序、任意切换次数，并比较最多 0/1/2 次和不限制次数四种解。

主配置三个开发种子的不限次数参考都采用 NR→Wi-Fi→LTE，两次净收益均为 248.96，严格高于对应的最多一次解。完整结果见 `RESULTS.md` 与 `outputs/physical_calibration_reference.csv`。参考只对声明的无队列 fresh-cohort 服务模型精确。

seed 100 另做实际包重放：一次参考计划的遥测/视频按时交付为 86.30%/70.72%；两次计划为 99.20%/99.01%。因此，这个任务中增加第二次迁移有实际服务价值。

两次结论具有配置范围。成本、中断和需求的 108 组敏感度中，96 组参考采用两次、12 组采用一次。其他高度、遮挡或需求也可能使三次或更多次合理。

## LAAVHA 的作用

学习模型预测 0.1/0.3/0.5 s 的状态，并通过任务监督训练属性权重。在线策略使用当前观测、预测置信度、正常优势确认和服务失败恢复；预测目的地持续性检查用于减少短暂的中间迁移。同样的可用性和确认规则用于强简单对照。

主场景验证算法能否以两次迁移维持服务。预测、注意力和 ALERA 的额外价值需要通过配对 QoS、消融和波动压力场景来区分；正常场景中简单对照同样取得两次也是有效结果。当前三个种子是开发集成验证，正式留出种子为 200–449。
