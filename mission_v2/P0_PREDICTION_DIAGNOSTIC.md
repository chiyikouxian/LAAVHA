# P0 诊断报告：预测为何带来负增益

日期：2026-11-10。基于已有 `outputs/audited_link_shadow_5/` 数据分析，无新仿真。

## 一句话结论

**预测的负增益主要来自 `policy.py` 第 143–146 行的"重定向"逻辑，而非评分融合或延迟确认。**
当 LSTM 预测 0.3 s 和 0.5 s 后的赢家与当前评分赢家不同，且预测目标已超过当前接入点的得分门限时，算法会强制切换到预测目标——即使预测目标的当前得分低于当前最优候选。由于 LSTM 在压力场景的 0.3 s/0.5 s 时域上均差于"持续当前值"基准，该重定向在 seeds 111 和 112 各引发 2 次额外往返，造成 2×100 ms 中断丢包。

---

## 证据逐步还原

### 1. 预测诊断数据

| 预测器 | 0.1 s MSE | 0.3 s MSE | 0.5 s MSE |
|---|---:|---:|---:|
| LSTM | 0.0252 | **0.0509** | **0.0832** |
| 持续当前值 | 0.0136 | **0.0455** | **0.0815** |
| 线性趋势 | 0.0175 | 0.0906 | 0.2379 |

LSTM 在三个时域全部落后于"持续当前值"。这是全程平均 MSE，在关键切换区间误差更大。

### 2. 三种预测路径分析

**路径 A：评分融合**（forecast_feature_fraction ≈ 30%）  
blended_score = (1−fff)×score(current) + fff×score(predicted)  
→ 改变评分赢家排名：5 颗种子合计 **0–1 次**（raw_candidate ≠ candidate 的步数）。影响极小。

**路径 B：延迟确认**（defer = True）  
当 LSTM 预测未来赢家 ≠ 当前候选 → 不开始向当前候选积累确认。  
→ 5 种子共 85 次 deferred_destination：59 次中性（gap=0，本来也不迁移），5 次有害（实际阻断了应迁移的步骤），21 次中间状态。不是主要原因。

**路径 C：强制重定向**（policy.py line 143–146）← **主要害因**
```python
if winners[0] == winners[1] and winners[0] != candidate:
    destination = winners[0]
    if usable[destination] and score[destination] - score[serving] > threshold:
        candidate = destination  # 强制覆盖！去预测的未来目标
```
条件：预测 0.3 s 和 0.5 s 均指向同一网络 `destination`，且该网络得分超过当前接入点（serving）门限。  
**并不要求 destination 得分超过当前评分赢家（candidate）。**

## 根本原因

重定向逻辑的比较基准是 **serving 得分**，而不是 **当前评分赢家（candidate）的得分**：
```
# 现行（错误）：
score[destination] - score[serving] > threshold

# 正确应为：
score[destination] - score[candidate] > margin
```
现行逻辑允许 destination 得分低于 candidate，只要它超过 serving + threshold 即可重定向。
这意味着即使预测目标已经不是当前最优，也会强制覆盖当前最优候选。

此外，LSTM 在 0.3 s/0.5 s 上差于持续值，而 `confidence >= 0.25` 门限用的是 1 步（0.1 s）局部误差衰减计算，不能反映多步预测质量——压力场景中置信度仍然偏高（均值 0.59–0.78），重定向条件频繁满足。

---

## 修复建议（按影响优先级）

### Fix-1：收紧重定向比较基准（优先级最高，单行改动）

```python
# policy.py 第 145 行，将
if usable[destination] and score[destination] - score[serving] > threshold:
# 改为
if usable[destination] and score[destination] - score[candidate] > threshold:
```

含义：预测目标必须在得分上**超过当前评分赢家**才允许重定向，不再允许替换一个得分更高的当前候选。
预期效果：消除 seeds 111/112 的额外往返，不影响预测正确时（destination > candidate）的合理重定向。

### Fix-2：提高重定向的置信度门限（防止不可靠预测触发）

```python
# 将重定向和延迟逻辑的条件门限从 0.25 提高
if (forecasts is not None and confidence >= 0.5 and  # 改自 0.25
        self.name not in ('no-pred', 'no-persistence') and not failed):
```

含义：只有近期 1 步误差足够小（confidence ≥ 0.5 对应误差 ≤ 0.104）时才触发预测干预。
注意：这是单因素调整，需与 Fix-1 分开运行消融以分离贡献。

### Fix-3：滚动多步误差估计替代 1 步置信度（中期）

现行 `confidence = exp(-error/0.15)` 只测 1 步（0.1 s）准确率，而重定向逻辑用的是
3–5 步（0.3–0.5 s）预测结果。应同时维护一个滚动 3–5 步误差估计，仅当多步误差
低于持续值基准时才允许重定向。

### Fix-4：no-fusion / no-persistence 消融运行（数据补充）

当前 40 次尚未包含 `no-fusion`（关闭评分融合保留前视检查）和 `no-persistence`
（关闭前视检查保留融合）。确认 Fix-1 修复后，用这两个消融分离路径 A 和 B 的贡献。
