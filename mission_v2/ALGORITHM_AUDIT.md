## 结论与修正顺序

切换次数接近，首先源于场景中绝大多数时刻无需多属性权衡。与此同时，Fuzzy-VHO 的成本方向存在错误，COPRAS 的收益/成本结构被适配掉，VIKOR 的定义也发生了变化。修复与重新命名应先于新实验；这三项改动的效果需要重新测量，不能预设一定扩大 LAAVHA 的优势。

## 1. 已核实的数值事实

计数核对：30 次运行、64 次迁移；C++ `handovers`、Python `raw_handover_count` 和动作日志计数全部一致。当前策略、模型、任务和 C++ 源码与该批实验 manifest 的指纹一致。

以下统计只描述 LAAVHA 自身两次运行的观测，不能作为所有策略共用一条、与动作无关的环境轨迹。

| 统计项 | seed 200 | seed 201 |
|---|---:|---:|
| 决策时刻 | 500 | 500 |
| 只有一个网络满足共同可用性条件 | 286 | 272 |
| 存在逐项不差于其他可用网络的候选，包括唯一可用的情况 | 472（94.4%） | 453（90.6%） |
| LAAVHA 与去预测版的接入动作一致 | 499/500 | 500/500 |
| LAAVHA 与 ALERA 的接入动作一致 | 500/500 | 500/500 |
| 预览阶段容量效用落在 0/1 端点的比例，统计三个网络 | 99.29% | 99.29% |
| 预测特征的实际平均融合占比 | 35.99% | 35.82% |

逐项比较使用当前五项 benefit features，可用性使用与策略相同的三样本窗口。占优包含相等关系。这是“改变正权重通常无法改变选择”的证据，不是对任意排序算法行为的数学保证。

预测平均占比约 36%，因此不能把差异小说成“预测没有被调用”。更准确的解释是：预测已进入决策，但当前任务很少需要它改变接入动作。

## 2. Fuzzy-VHO：成本方向反转

位置：`baseline_snapshot/fuzzy_vho.py:85–103`；当前 `policy.py:77–79` 直接调用该快照。此处快照是历史实现证据，不应直接覆盖，应在新的活动实现中修复。

先执行 `1 - normalized_cost`，使延迟和丢失率都变为越大越好；后续规则却仍把这两项的 Low 当作 Good、High 当作 Poor。两次方向解释不一致。

固定数值例子，列顺序为 SINR、接收功率、延迟、估计容量、丢失率：

```text
网络 0: [10, -80,   5, 10, 0.01]
网络 1: [10, -80,  20, 10, 0.10]
网络 2: [10, -80, 100, 10, 0.40]
```

信号和容量完全相同，网络 0 的延迟和丢失率均最优。三个网络也都满足共同可用性门限，安全筛选不会排除网络 2。

现函数输出分数 `[0.15, 0.272807, 0.90]`，选择最差的网络 2。在内存中将成本效用 High 对应 Good、Low 对应 Poor 后，同一例子输出 `[0.90, 0.694872, 0.15]`，选择网络 0。未将此修正写回活动代码。

修正后的验证应包含：单独改善延迟、单独改善丢失率、联合改善所有指标、常量列、并列与不可用候选。当前文件只在 `__main__` 下检查一个整体优势例子，现有 `tests/` 没有验证这组模糊规则。

## 3. COPRAS 与 SPOTIS：应修复 COPRAS，不能强行制造排名差异

位置：`policy.py:75–76`。

现 COPRAS 为 `(f + epsilon) @ entropy_weights`，没有保留收益/成本分组和 COPRAS 的列和归一化。它与当前 SPOTIS 的 `1 - (1-f) @ entropy_weights` 几乎完全相等，差别仅为约 `10^-9` 的常量。

SPOTIS 在固定 `[0,1]` 边界、理想点全为 1、指标均为 benefit 时，规范距离本来就是 `sum(w * (1-f))`。与已安装 pymcdm 对照的最大差为 `1.11e-16`。其加权和等价性本身正确。

新 COPRAS 应明确选择一种数据语义：保留正值的原始收益/成本指标及类型，或以 benefit features 为基础另行声明变体。若采用标准收益/成本结构，延迟和丢失率保持成本方向，统一处理负 dBm 指标到正值收益刻度、零列、零成本和常量列，固定这些转换后再对照参考公式。

历史快照 `baseline_snapshot/madm_comparison.py:64–79,115–136` 保留了成本类型和库实现，但包括逐时 min-max、epsilon 截断与回退，因此也不能直接当作完整原作者系统的证据。

修正后不同方法仍可得到相同排名；验证目标是公式一致、方向正确，而不是强制各方法产生不同次数。

## 4. VIKOR：固定理想点遗憾与标准 VIKOR 不同

位置：`policy.py:72–74`。

现实现使用 `regret = (1-f) * w`。标准 VIKOR 使用每个指标的候选理想值和反理想值，对差距作逐列归一化；转换为 benefit 后，其非恒定列项为：

```text
w_j * (max_i f_ij - f_ij) / (max_i f_ij - min_i f_ij)
```

即使输入 f 已在 `[0,1]`，某一时刻的候选也不一定覆盖 0 和 1，两式仍可能得到不同选择。证据文件保存了一个使用同一熵权的有限值例子：现实现选择网络 1，参考 VIKOR 选择网络 2。

若恢复标准 VIKOR，需要为常量指标、全体 group utility 相同、全体 individual regret 相同明确约定：没有辨别力的项贡献为零；不可在异常后静默调用另一个算法。已安装 pymcdm 对部分退化矩阵会报错或产生 NaN，单纯调用库并不能解决这些边界。

## 5. 各方法的实际含义

| CLI 标识 | mission_v2 当前做法 | 与旧快照/常见定义的差异 |
|---|---|---|
| `topsis-q` | 固定工程效用、每步熵权、向量 TOPSIS | 旧快照先逐时 min-max，熵权还减去列最小值 |
| `saw` | 随任务切换两组权重的效用加权和 | 旧 SAW 使用固定 `[.25,.15,.20,.30,.10]`；新方法应明确叫 task-aware SAW |
| `gra` | 灰关联系数加熵权 | 旧 GRA 是逐时 min-max 后的等权系数平均 |
| `vikor` | 固定理想点的遗憾折衷 | 不是当前候选理想/反理想归一化的标准 VIKOR |
| `copras` | 熵权 benefit 加权和 | 收益/成本结构与列和归一化被移除 |
| `spotis` | 固定效用边界下的加权理想距离 | 此公式合理；若权重每步变化，不能笼统承诺完整排序不变性质 |
| `fuzzy-vho` | 历史 NumPy 模糊规则加共同控制层 | 存在成本方向错误；五指标规则也不等同于原论文中任意特定完整系统 |
| `strongest-signal` | 最大 SINR 加共同控制层 | 应标记 strongest-SINR with shared guards |
| `topsis` | 手工任务权重 TOPSIS 加共同控制层 | 合理的强简单对照，应保留 |
| `trend` | 三样本差分线性外推，加预测持续性检查 | 是具有前视与确认机制的强对照 |
| `ewma` | 五样本等权移动平均 | 实际不是指数加权移动平均；论文已有别名说明 |

熵权每步重新计算，本身也是数据依赖的动态权重。论文应比较“学习且显式接受任务上下文的权重”和“数据离散度驱动的熵权”，不能把后者一概写成不随状态变化的常量。新草稿引言仍有此表述遗留。

## 6. 共享机制与阈值尺度

当前可用性：三样本平均估计容量至少 0.1 Mbps、延迟不超过 200 ms、丢失率小于 0.5。正常迁移使用优势阈值和三次连续确认；失效恢复改为两次确认、零阈值。所有网络不可用时保持当前接口。共同规则既保证安全，也贡献了稳定性。

共同的数值阈值 0.03 并不等于共同的行为强度。例如 strongest-SINR 的分数是 `(SINR+50)/130`，阈值 0.03 对应 3.9 dB 优势；TOPSIS 分数差 0.03 没有同样的物理含义。改用两组比较：

1. 保留相同控制层、各自经开发集校准的排序对照，用于比较排序/预测增益。
2. 明确列出的控制层消融，用于区分平滑、确认、预测持续性与学习模块的作用。

两组使用同一物理可用性边界、迁移中断和业务。为各方法提供相同的开发调参预算，参数冻结后再评测。不要通过只移除其他算法的安全规则来归因预测收益。

## 7. 消融与 ALERA 的版本定义

`no-pred` 保留同一 checkpoint 的学习权重，关闭预测融合，同时关闭依赖预测的目的地持续性检查。它衡量的是“整个预测决策分支”的贡献，并不单独识别预测融合和持续性检查。推理仍计算预测，不能用它直接测量移除 LSTM 后的运行开销。

`no-attention` 用手工任务权重代替学习权重，保留预测和持续性检查；这是有效的强权重替代对照，但不同于旧稿/旧实现使用熵权的 LAAVHA-A。后续建议分别设置 fixed-task、uniform、entropy 三个权重替代，保留明确名称。

mission_v2 ALERA 使用 score increments 和 SINR increments 的标准差，普通确认窗口固定为 3。旧投稿稿与历史增强实现使用原值标准差，并有速度控制的动态确认窗口。新隔离草稿方法段已说明 mission_v2 的增量版本。应明确是算法版本变化，不能把 mission_v2 结果用于验证旧稿中未实现的动态窗口公式。

当前 SINR 在成功接收相关回调中更新，容量另有 0.5 s 新鲜度判定。策略和风险层没有接收到信号年龄。失去新观测时，固定旧值可能被理解为低波动，应把观测年龄/有效性与预测不确定性分别记录。

## 8. 缓存复用和配置入口

`pilot.py:20–32` 复用现有 summary 时检查三个场景参数、config 哈希和学习模型哈希，没有比较当前策略/模型源码或二进制哈希。`run.py` 会保存这些指纹，但 pilot 尚未据此拒绝旧结果。更改算法后复用旧目录可能跳过运行；新版本应拒绝指纹不匹配，并始终输出新目录。

`run.py --stress` 仅传入 abstract backend；真实 ns-3 分支使用 `--shadow-db`。两者不能混用。批跑入口没有透传 threshold/window/alpha，若要公平开发调参，需要扩展并记录这些参数。

`SceneLoss` 的空间场只使用位置与 seed，不区分 NR/LTE/Wi-Fi 的链路标识。三个接口共址时，相同 `shadow_db` 对三条链路施加相同的 dB 起伏；将其从 0 调大，仍不等同于具有链路差异的波动或独立网络负载。

## 9. 建议的实现验收顺序

1. 在新活动版本中修正 Fuzzy、实现标准 COPRAS/VIKOR，保留历史快照与已有实验目录。
2. 通过成本/收益单调性、候选置换、常量列、并列、缺测和参考矩阵验证；算法允许相同选择。
3. 分离评分、共享控制和诊断输出；记录原始赢家、可用性、分数差、有效阈值/窗口、失效恢复、观测年龄、预测融合比例和拒绝原因。
4. 固定消融含义和 ALERA 版本，再实施场景检验计划。单元数值检查通过后，才进入用户授权的物理开发运行。
5. 新实验冻结 manifest 应包含活动实现、配置、checkpoint、二进制与场景生成过程指纹，最后再生成论文表格。
